# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

git-agent — агентская система на LangChain/LangGraph для сканирования и разбора репозиториев. Python 3.13, управляется через `uv`.

## Монорепа

Верхний уровень: `agent/` (Python-агент — всё описанное ниже: core/infra/deps/pkg/tests/evals/formal, pyproject), `backend/` (Go-сервис «hub»: мониторинг GitHub/GitLab, пользователи+OAuth-связки, создание сэндбоксов, Таски в RabbitMQ; модуль `github.com/vnkjd/git-agent/backend`, `cmd/hub`; дефолты пустых полей при создании сущностей — `internal/hub/domain/defaults.go` (`ApplyDefaults`, env-часть — `config.Defaults` из тех же ключей .env, что у агента), новые create-ручки проводи через него), `frontend/`, `deploy/` (общая инфраструктура), `migrations/` (`migrations/agent/` — SQL агента, симлинк `agent/migrations` для `python -m migrations.migrate`; `migrations/backend/` появится с первой миграцией). Общие наверху: `CONTEXT.md`, `openspec/`, `.wayfinder/` (карта планирования backend), `Taskfile.yml` (python-таски исполняются с `dir: agent`; `task backend:build|run`). Пути в разделах ниже — относительно `agent/`.

Зависимости: langchain 1.x, langgraph 1.x, langfuse, langsmith, pydantic-settings.

- `core/config.py` — единая точка конфигурации: `load_dotenv()` + `Settings` (pydantic-settings), синглтон `settings`. Новые ключи добавляй туда и в `.env.example`.
- `infra/` разложен по пакетам: `infra/db/` (postgres, run_store, connections), `infra/sandbox/` (opensandbox, localsandbox, sandboxes, instances), `infra/server/` (FastAPI-gateway: app, wire, graphview); `infra/mcp.py` — загрузчик MCP-тулов. `main.py` — точка входа: `app = create_app()` (запуск `uvicorn main:app`).
- `deps/` — композиционный корень (единственный слой поверх core+infra): `deps.app_deps()` — async-CM, собирающий чекпоинтер, MCP-тулы, рантаймы (pipeline+agent) и гасящий их **graceful** в порядке зависимостей (агенты/воркеры → чекпоинтер → async-пул → sync-пул; песочницы не трогаем — no-TTL). Lifespan gateway и `main.py` поднимаются через него; на SIGINT/SIGTERM uvicorn (`timeout_graceful_shutdown`) уводит в разбор. Явные `close_pool`/`close_async_pool` — в `infra/db/postgres.py`.
- `infra/sandbox/opensandbox.py` — `create_sandbox()`: песочница через OpenSandbox SDK. Сервис поднимается командой `docker compose -f deploy/docker-compose.yml up -d` (порт 8090, dev-ключ `dev-local-key`).
- `core/tracing/` — фабрика трейсинг-коллбэков (референс deerflow/tracing): `build_tracing_callbacks()` — fail-fast при включённом-но-ненастроенном провайдере, `inject_langfuse_metadata()` — session/tags на корневой трейс; env `LANGSMITH_*`/`LANGFUSE_TRACING`+ключи читаются здесь, не в Settings. Monocle не портирован (нет OTel-инструментора).
- `pkg/logger.py` — structlog: pretty в консоль (`LOG_FORMAT=json` — JSON, прод), файлы `logs/app.jsonl` (всё, хронологически) и `logs/error.jsonl` (WARNING+). Бери логгер через `from pkg.logger import get_logger`; контекст хода/запроса (`instance_id`, `event_id`, `turn`, `request_id`) привязывай через `bound(...)`, а не передавай руками — он попадает в каждую строку блока, `exc_info` сворачивается в `error="Type: msg"`. Раннер получает сквозной `X-Request-ID` от hub.
- `core/memory/` — пресеты управления контекстом (`config.py` — класс, `prompts.py` — промпты, `presets.py` — инстансы, резолвер в `__init__.py`; `resolve_memory_preset`): явный аргумент > env `GIT_AGENT_MEMORY_PRESET` > продакшен-пресет под модель (`prod_v2`, для провайдеров вне long-context allowlist — `prod`); неизвестное имя или несовместимый провайдер — ошибка, не фолбэк. Новые конфигурации компакции добавляй пресетом сюда, не разрозненными флагами.
- `openspec/` — spec-driven разработка через OpenSpec. `openspec/specs/` — действующие поведенческие спеки (agent-graph, repo-scan, repo-parse, durable-runs, lead-delegation, memory-presets, eval-harness) — источник правды о том, ЧТО система обязана делать; исполняемые зеркала (Lean-модель, тесты) — о том, что она делает. Цикл: `/opsx:propose` (proposal + спек-дельты + tasks) → `/opsx:apply` → `openspec archive` (дельты вливаются в specs). Меняешь наблюдаемое поведение — сначала change со спек-дельтой; рефакторинг/внутренности — без OpenSpec.
- Postgres (порт 5433, поднимается тем же compose): таблицы `repositories`, `runs` (commit_sha + llm_api_base/key/model на каждый ран) и чекпоинты LangGraph (`PostgresSaver`). Миграции — нумерованные SQL в `migrations/`, применение: `uv run python -m migrations.migrate` (идемпотентно). Тесты работают с БД в **отдельной тестовой БД** (`<db>_test`, по умолчанию `git_agent_test`; override — `TEST_DATABASE_URL`): `tests/conftest.py` на импорте создаёт её, мигрирует, чистит и сеет `repositories` id=1 — рабочая БД тестами не загрязняется.
- `.env` в gitignore; шаблон — `.env.example`.

## Граф Рана

`core/agents/graph.py::build_graph(sandbox, model)` — линейный StateGraph: `scan → parse → report` (состояние `RepoState` в `state.py`, узлы в `nodes.py`). Ошибка узла кладётся в `state["error"]` и уводит граф сразу в report; песочницу провиженит и отпускает воркер рантайма. Узлы зависят от порта `core/ports.py::Sandbox` (`repo_dir`, `id`, `run`, `close`), а не от infra. Пресеты песочниц — таблица `sandboxes` (kind: opensandbox/local/ssh), создание по имени: `infra/sandbox/sandboxes.py::create_sandbox_by_name`. **Экземпляры** (реально провиженные сэндбоксы) учитываются отдельно в `sandbox_instances` (external_id, run_id, status `alive|dead`): OpenSandbox создаётся **без TTL** (`create_sandbox(timeout=None)`), воркер его **не убивает** — жизненным циклом рулит оператор. Выбор даёт `infra/sandbox/sandboxes.py::provision_sandbox(run_id, name, *, is_resume)` → `(sandbox, reused)`: при resume переподключается к живому Экземпляру Рана (`Sandbox.connect`, `reused=True` ⇒ без повторного клона), иначе создаёт свежий и пишет Экземпляр; неудачный reconnect метит старый `dead` + fallback. Ручное убийство — `infra/sandbox/instances.py::kill_sandbox` (`destroy` + `status=dead`, идемпотентно) через gateway `GET/POST /api/sandboxes/instances[/{id}/kill]` (фронт — SandboxesScreen, панель INSTANCES). Удаление Рана (`DELETE /api/runs/{id}`) сначала убивает удалённые сэндбоксы Рана (`kill_run_instances`), затем `delete_run` сносит и строки `sandbox_instances` (иначе FK на `runs` блокирует удаление). Порт `Sandbox.close()` = отпустить локальные ресурсы (НЕ kill). LLM — OpenAI-совместимый endpoint (`core/agents/llm.py::make_model`, ключи per-run). Тесты: `tests/unit` (без сервисов), `tests/integration` (Postgres), `tests/e2e` (OpenSandbox); `task test:unit` и т.д..

## Точка входа и режимы

`main.py` — точка входа сервера: `app = create_app()` (запуск `uv run uvicorn main:app --port 8080` или `task server`, порт/host из `SERVER_*` в .env). Ран исполняется через durable-рантайм (не напрямую граф); режим (`pipeline` — линейный scan→parse→report, дефолт; `agent` — ReAct-лид с делегированием) приходит полем `mode` в HTTP-submit. Какой граф исполнять — задаёт `GraphProfile` (`core/runtime/profile.py`: `build`/`make_input`/`extract_report`/`stream_modes`/`run_config`); воркер зависит от профиля, не от конкретного графа. Дефолт — `PIPELINE_PROFILE`; лид — `core/lead/build_lead_profile()` (собирает `build_agent` + sandbox-тулы + `task`-тул + `loop_detection`/`token_budget`, вход — задача текстом, отчёт — финальный ответ). Gateway резолвит commit_sha через `git ls-remote`/`rev-parse` (идемпотентность), поднимает `AsyncPostgresSaver` для resume, стримит `task_*`-события по SSE.

## Runtime (core/runtime/)

Durable-исполнение Ранов по образцу deer-flow: «ран — это ресурс, а не запрос». `Runtime.submit()` идемпотентен: admission — атомарный `claim` CAS на строке `runs` (unique `(repository_id, commit_sha, llm_model)`); упавший ран при resubmit возобновляется с чекпоинта под тем же id. Lease+heartbeat с fail-closed fence (`ownership_lost` ⇒ ноль durable-записей, но `publish_end` всегда), orphan recovery через `claim_for_takeover` (истечение lease перепроверяется в момент записи), отмена — `cancel_requested_at`-мейлбокс, читаемый при продлении lease. Стрим — `MemoryStreamBridge`: реплей по курсору O(1), честный `StreamGap` при выпадении из буфера. Терминальные статусы неперезаписываемы; финализация воркера отменоустойчива (shield-loop). Порты `RunStore`/`StreamBridge` — в `core/ports.py`, PG-адаптер — `infra/db/run_store.py`, memory-варианты — исполняемая спецификация (`tests/unit/test_runtime.py`; PG-порт-тесты — `tests/integration/test_run_store_pg.py`). Формальная модель инвариантов — `formal/RuntimeCore.lean` (Lean 4). Доказательства проверяются **в pytest** (`tests/unit/test_formal.py` шеллит `lean`, требует exit 0 + ноль `sorry`; скип без lean), так что `task test`/`task check` их верифицируют; `task formal` — отдельно. lean — в `~/.elan/bin` (не в PATH по умолчанию). Карта портирования — `formal/MAPPING.md`; статусная машина `LEGAL_TRANSITIONS`+`assert_transition` в `schemas.py`, зеркала теорем — `tests/unit/test_invariants.py`. Меняешь семантику переходов/admission — сначала обнови модель (тесты должны пройти) и карту.

## Сабагенты (core/subagents/)

Лид + делегирование через тул `task` (референс deer-flow, строго звезда глубины 1 — у детей тула `task` нет структурно). Wiring — в докстринге `core/subagents/__init__.py`. Ключевое: `SubagentResult.try_set_terminal` — first-writer-wins (владение: executor → COMPLETED/FAILED, task-тул → TIMED_OUT/CANCELLED; отмена в executor НЕ терминализирует, а перебрасывает); причина капа — аддитивное поле `stop_reason`, не новый статус; квитанции (`receipts.py` — формат+парсер+верификатор+промпт в одном модуле), верификация цитат по снапшоту леджера цитирующего хода; лимиты — `SubagentLimitMiddleware` (вырезание task-вызовов + `finish_reason=stop`; `max_concurrent`=`maxSubagents`, `max_total_per_run`=`maxTotalSubagents` из лимитов Рана), admission — `SubagentCapacity` (FIFO, лимиты заморожены конструктором); события `task_*` — в custom-стрим. Два таймаута конфигурятся per-run через лимиты Рана (наряду с `maxSubagents`/`tokenBudget`): `subagentTimeout` (потолок исполнения Сабагента, `wait_for` в task-туле, дефолт 600s из `SubagentConfig`) и `queueTimeout` (ожидание слота в capacity, дефолт 300s); резолвятся в `core/lead/graph.py::_lead_features`. Ребёнку НИКОГДА не передавать `configurable`-ключи в конфиг. Тесты герметичны: `tests/conftest.py` глушит tracing-флаги (LangSmith-автотрейсинг сериализацией фейк-модели выпивает её итератор — реальный пойманный баг).

Термины проекта — в `CONTEXT.md` (глоссарий); используй их в коде и обсуждениях.

## Evals (evals/)

Eval-харнес по образцу ai-tutor-app: батарея = замороженный JSONL с запиненными `(repo_url, commit_sha)` и руками написанными бинарно-проверяемыми фактами (`evals/data/repos.v1.jsonl`; ground truth НИКОГДА не от LLM; правка = новый `_v2`-файл + запись в `DEPRECATED_BATTERIES`). Разделение фаз: `run_battery.py` — единственный модуль, трогающий приложение (платный, пишет вечные `runs/<name>/{run_config.json, bundles.jsonl}`); `grade.py`/`validity.py`/`report.py` — офлайн и app-free (R1: не импортируют core/infra — грейд повторяем вечно). Константы приложения (терминальные статусы, kind usage-события, тип task_started) — зеркалированы в `evals/common.py`, дрейф ловит `tests/unit/eval/test_harness.py::test_signal_mirror_matches_app` (единственный eval-тест, которому можно импортировать app). Ключевые механики: fingerprint манифеста (git sha + source_tree_sha256 включая незакоммиченное + хэш батареи + резолвнутый пресет + прайс-снапшот) — несовпадение с существующим `run_config.json` = отказ писать в тот же `--out`; identity-неймспейсинг — в `runs.commit_sha` кладётся `sha12~fp12~mode~preset~tN` (durable-метка, реальный пин едет через `checkout_ref`), чтобы армы не коллидировали по идемпотентности submit; tri-state грейд (None = неизмеримо ≠ fail), tool-fair (structured + prose оценка каждого факта, кросс-режимный хедлайн — prose); validity-гейт («ось эксперимента реально применилась?») исключает ран из скоринга целиком; `price_run` — верхняя граница, неизвестная модель → None, не 0. Прогоны с реальными деньгами — только по явной команде пользователя.

## HTTP-gateway (infra/server/) и фронтенд (frontend/)

`infra/server/app.py` — FastAPI-адаптер над фасадом `Runtime`; wire-контракт — `frontend/docs/openapi.yaml` (авторитетный, camelCase). Запуск: `uv run uvicorn main:app --port 8080`. Роуты: runs (list/get/submit/cancel/resume/report), SSE `/api/runs/{id}/events` (live через `Runtime.subscribe`, терминальный ран — реплей durable-истории; wire-курсор — seq из bridge-id `{ms}-{seq}`), граф (`infra/server/graphview.py`: топология из LangGraph `get_graph`, статусы из run_events; агентный ран — звезда лид→сабагенты по task_*-событиям), справочники (sandboxes, capabilities, memory-presets, connections — таблица из `migrations/005`). Инвариант redaction: `llm_api_key`/`connections.api_key` наружу только маской (`infra/server/wire.py::mask_key`). Gateway держит по Runtime на режим (pipeline и agent, лид-профиль) над общими store/bridge: submit — по `mode` из запроса, resume/cancel — по фактическому режиму Рана (агентность выводится из событий); задача Рана — поле `instructions`. Пост-ран чат (`Runtime.chat`, только agent-режим): `GET/POST /api/runs/{id}/chat` — продолжает LangGraph-тред Рана (`thread_id=str(run_id)`) новым `HumanMessage`, БЕЗ durable-admission и без изменения терминального статуса/Отчёта; песочница переподключается через `provision_sandbox(is_resume=True)`, ходы стримятся (SSE) и персистятся отдельным типом события `chat` (граф/Отчёт их игнорируют); per-run `asyncio.Lock`. Фронт — `ChatPanel` на экране завершённого агентного Рана. Фронт: `task front` (bun + vite dev, :5173; vite-прокси `/api` → :8080); единственный API-адаптер — http (mock удалён). Всё разом: `task app`.

## Security-ревью (agent-режим)

Лид в agent-режиме — авторизованный security-ревьюер кода (`core/lead/graph.py`, промпт `LEAD_SYSTEM_PROMPT`, референс strix). Инструменты: `report_finding` (фиксация Находки — severity/CWE/CVE/файл-строки/evidence/remediation; `core/agents/findings.py`), `load_skill` (справочник методик, `core/skills/` — курированные markdown-скиллы из strix по классам уязвимостей; детям-сабагентам даётся только `load_skill`, `report_finding` консолидирует лид). Находки собираются из `report_finding`-tool_calls в истории сообщений (`collect_findings`) — без кастомного state; Отчёт агентного Рана = `{summary, findings}`. CVE-интеллект: cve-mcp-server (`infra/mcp.py`, `CVE_MCP_PATH` в .env → stdio через `uv run --project`) подключается как MCP, тулы уезжают за deferred-каталог (`core/tools`, `tool_search`); сервер недоступен ⇒ warn+continue. Наружу — `infra/server/wire.py` (findings в Отчёте) + `frontend` ReportScreen (панель FINDINGS). Скоуп — статический анализ кода; live-тулинг strix (browser/proxy/exploit) не портирован.

## Архитектура

Пишем по гексагональной архитектуре (ports & adapters): `core/` — домен и прикладная логика, не зависит от способа запуска: конфиг, пресеты памяти `core/memory/`; агент — `core/agents/` (состояние, фабрика `build_agent` + `RuntimeFeatures`, llm, узлы/граф); middleware фич — `core/middleware/` (история рана в `run_events` пишется воркером через порт `RunStore.add_event`, отдельного history-middleware нет); сабагенты — `core/subagents/`; тулы — `core/tools/` (`sandbox.py` — sandbox-тулы над портом Sandbox, единственный рабочий toolset; плюс lean-ядро deerflow/tools: MCP-тегирование, sync-обёртка async-тулов, deferred-каталог `tool_search` с fail-closed сборкой и сборщик `get_available_tools` с дедупом config > builtins > mcp — standalone до появления MCP-тулов у лида). Адаптеры к внешнему миру — по краям (`infra/` — клиенты внешних систем, `infra/db/postgres.py` — пул psycopg + операции repositories/runs; `migrations/` — схема БД, `deploy/` — инфраструктура, `main.py` — точка входа сервера). Зависимости направлены внутрь: core не импортирует из main и адаптеров.

## Commands

Основной путь — Taskfile (`task --list`): `task up`/`down` (инфраструктура), `task migrate`, `task lint`/`fix`/`fmt` (ruff, конфиг в pyproject.toml), `task test` (pytest, включая Lean-верификацию), `task backend:lint` (golangci-lint, `backend/.golangci.yml`; ставится `go install .../golangci-lint/v2/cmd/golangci-lint@latest` под текущий toolchain), `task check` (lint+test обеих частей), `task server`/`task app` (gateway/всё приложение). Напрямую: `uv add <package>` — зависимости (pyproject.toml руками не редактировать), `uv sync` — окружение.
