# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

git-agent — система security-ревью git-репозиториев: Go-hub принимает вебхуки GitHub/GitLab и публикует События, Python-раннер (LangChain/LangGraph) поднимает долгоживущих Экземпляров Агентов, которые исследуют код в песочнице и пишут Находки. Python 3.13, управляется через `uv`.

## Монорепа

Верхний уровень: `agent/` (Python-раннер — всё описанное ниже: core/infra/deps/pkg/tests/evals, pyproject), `backend/` (Go-сервис «hub»: мониторинг GitHub/GitLab, пользователи+OAuth-связки, Сборки/Экземпляры, sandbox-подключения и Экземпляры Сэндбоксов, реестр раннеров, События в RabbitMQ; модуль `github.com/vnkjd/git-agent/backend`, `cmd/hub`; дефолты пустых полей при создании сущностей — `internal/hub/domain/defaults.go` (`ApplyDefaults`, env-часть — `config.Defaults` из тех же ключей .env, что у агента), новые create-ручки проводи через него; сквозной `trace_id` — `X-Trace-Id` (`pkg/trace`: middleware принимает/генерирует, `trace.Logger(ctx)` для логов, заголовок во все исходящие вызовы, `traceId` в Rabbit, колонки `events/activity.trace_id`)), `frontend/`, `deploy/` (общая инфраструктура), `migrations/` (`migrations/agent/` — SQL агента, симлинк `agent/migrations` для `python -m migrations.migrate`; `migrations/backend/` — схема `hub.*`, `docs/ERD.md`). Общие наверху: `CONTEXT.md` (глоссарий), `openspec/`, `.wayfinder/` (карта планирования backend), `Taskfile.yml` (python-таски исполняются с `dir: agent`; `task backend:build|run|test`). Пути в разделах ниже — относительно `agent/`.

Зависимости: langchain 1.x, langgraph 1.x, langfuse, langsmith, pydantic-settings, aio-pika, cryptography.

- `core/config.py` — единая точка конфигурации: `load_dotenv()` + `Settings` (pydantic-settings), синглтон `settings`. Новые ключи добавляй туда и в `.env.example` (общий на hub/раннер/фронт; `RABBITMQ_URL`, `SECRETS_KEY`, `RUNNER_TOKEN` — общие с hub).
- `infra/` разложен по пакетам: `infra/db/` (`postgres.py` — async-пул psycopg; `hub_store.py` — адаптер порта `InstanceStore` над `hub.*`), `infra/sandbox/` (`opensandbox.py` — адаптер OpenSandbox SDK, `sandboxes.py::connect_hub_sandbox`), `infra/server/runner_api.py` (FastAPI-роутер раннера), `infra/hub_client.py` (httpx: регистрация/heartbeat/форвард), `infra/rabbit.py` (консьюмер aio-pika), `infra/mcp.py` — загрузчик MCP-тулов. `runner.py` — точка входа: `app = create_runner_app()` (`uvicorn runner:app --port 8082`, `task runner`).
- `deps/container.py` — композиционный корень (единственный слой поверх core+infra): `deps.runner_deps()` — async-CM, собирающий `HubInstanceStore`, `HttpHubClient`, `AsyncPostgresSaver`, `EventExecutor`, `RunnerService` и три фоновых цикла (консьюмер Rabbit, heartbeat, idle-репер); гасит их **graceful** (циклы → Экземпляры running→down → HTTP-клиент → чекпоинтер → пул; песочницы не трогаем — ими владеет hub).
- `core/tracing/` — наблюдаемость хода. `TurnTracer` (`turn_tracer.py`) — LangChain-коллбэк, который пишет в лог каждый LLM-вызов (агент, `duration_ms`, токены, какой тул запрошен) и каждый тул-вызов (агент, тул, превью аргументов, `duration_ms`, размер вывода), а в конце хода — `turn summary` (счётчики и время по тулам и агентам). Вешается `EventExecutor._run_config` в `config["callbacks"]` корневого `astream` вместе с провайдерами (`build_tracing_callbacks()`: LangSmith/Langfuse, fail-fast при включённом-но-ненастроенном; `inject_langfuse_metadata()` — session = thread Экземпляра). Сабагент наследует **только** `callbacks` родителя (`ensure_config()["callbacks"]` + свой коллектор) — так его вызовы попадают в трейс лида с тегом `subagent:<name>`; `configurable` родителя ребёнку не передаётся никогда. Env `LANGSMITH_*`/`LANGFUSE_*` читаются в `core/tracing/config.py`, не в Settings.
- `pkg/logger.py` — structlog: консоль pretty на TTY / JSON в пайпе (`LOG_FORMAT`), JSON по уровням в `logs/<level>.jsonl`, порог `LOG_LEVEL`; uvicorn и warnings идут через тот же конвейер. Бери логгер через `from pkg.logger import get_logger`. Контекст хода (`instance_id`, `event_id`, `turn`, `trace_id` — `pkg/trace.py`: из `traceId` Rabbit-сообщения либо `X-Trace-Id` HTTP, иначе свой) вешается один раз `structlog.contextvars.bound_contextvars()` на входе в `RunnerService.handle_event/chat/terminal` — дальше его несут все логи ниже по стеку. Исключение логируется **один раз** там, где обрабатывается (`log.exception`), причина — `pkg/errors.py::describe(exc)` (тип + текст + цепочка `__cause__`); границы (консьюмер Rabbit, HTTP 500) пишут только краткий факт без второго трейсбека. Фоновые циклы раннера (консьюмер, heartbeat, idle) под супервизором `deps/container.py::_supervised` — падение = лог с трейсбеком + рестарт с backoff. HTTP-ошибки раннера — тот же wire-формат ApiError `{"error":{"code","message"}}`, что у hub (`infra/server/runner_api.py::install_api`); `InstanceUnavailableError` → 409, `SandboxNotProvisionedError` → 424; ошибка внутри SSE — кадром (`activity`/`run_failed`/`output`), не обрывом.
- `core/memory/` — пресеты управления контекстом (`config.py` — класс, `prompts.py` — промпты, `presets.py` — инстансы, резолвер в `__init__.py`; `resolve_memory_preset`): явный аргумент > env `GIT_AGENT_MEMORY_PRESET` > продакшен-пресет под модель; неизвестное имя или несовместимый провайдер — ошибка, не фолбэк. Новые конфигурации компакции добавляй пресетом сюда, не разрозненными флагами.
- `openspec/` — spec-driven разработка через OpenSpec. `openspec/specs/` — действующие поведенческие спеки (runner, lead-delegation, security-analysis, memory-presets, eval-harness) — источник правды о том, ЧТО система обязана делать. Цикл: `/opsx:propose` (proposal + спек-дельты + tasks) → `/opsx:apply` → `openspec archive` (дельты вливаются в specs). Меняешь наблюдаемое поведение — сначала change со спек-дельтой; рефакторинг/внутренности — без OpenSpec.
- Postgres (порт 5433, поднимается `task up`): схема `hub.*` (backend-миграции; раннер читает/пишет `hub.runners`, `hub.agent_instances`, `hub.processed_events`, `hub.activity`, `hub.findings`, `hub.reports`, `hub.sandbox_instances`) и чекпоинты LangGraph (`AsyncPostgresSaver`, тред = `thread_id` Экземпляра). Миграции — нумерованные SQL в `migrations/`, применение: `uv run python -m migrations.migrate` (идемпотентно, оба сервиса). Тесты работают в **отдельной тестовой БД** (`<db>_test`; override — `TEST_DATABASE_URL`): `tests/conftest.py` на импорте создаёт её, мигрирует и чистит чекпоинты; `hub.*` чистят сами интеграционные тесты.
- `.env` в gitignore; шаблон — `.env.example`.

## Раннер (core/runner/)

Раннер — консьюмер Событий RabbitMQ (спека `openspec/specs/runner`, тикеты `.wayfinder/tickets/001,004,005,010`). Экземпляр Агента — долгоживущий агент Репозитория (один на (Сборка, Репозиторий)), статусы `down|running`; гарантии дают дедуп-журнал `hub.processed_events` + чекпоинты, не ack (auto-ack). `RunnerService` (`service.py`) — слоты (`asyncio.Semaphore`), клейм Экземпляра CAS'ом в БД (`InstanceStore.claim_instance`), форвард События держателю на другом раннере (`HubClient.forward_event` → `POST /instances/{id}/events`), idle-выгрузка, heartbeat, регистрация в hub. `EventExecutor` (`executor.py`) — один ход лид-графа на тред Экземпляра: подключается к песочнице (`connect_hub_sandbox`, песочницу создаёт юзер в hub — нет живой ⇒ `SandboxNotProvisionedError`, Событие не обрабатывается), готовит репо (`core/repo.py`), стримит `updates`+`custom`, плюс hub-тулзы результатов (`build_hub_security_tools`: `report_finding` → `hub.findings`, `write_report` → `hub.reports`). Активность хода (`activity.py`) пишется в `hub.activity` и стримится SSE; стрим-консоль к песочнице — `terminal` (обёртка команды с маркером кода/cwd). Порты — `core/runner/ports.py` (`InstanceStore`, `HubClient`); секреты `*_enc` — AES-GCM (`crypto.py`, ключ `SECRETS_KEY`, общий с hub). HTTP API раннера (`infra/server/runner_api.py`, `backend/docs/openapi.yaml`): `raise` (200 running / 202 queued), `stop` (cancel хода; `processed_at` остаётся NULL — ре-публикация hub'ом возобновляет), `events` (форвард), `chat` (SSE, ход в тот же тред), `activity` (SSE с реплеем), `terminal` (SSE). Какой граф исполнять — задаёт `GraphProfile` (`core/lead/profile.py`: `build`/`make_input`/`extract_report`/`stream_modes`/`run_config`); раннер зависит от профиля, не от графа. Единственный профиль — `core/lead/build_lead_profile()` (собирает `build_agent` + sandbox-тулы + `task`-тул + `loop_detection`/`token_budget`; лимиты — из `limits` Сборки).

## Сабагенты (core/subagents/)

Лид + делегирование через тул `task` (`core/tools/delegation/task.py`; референс deer-flow, строго звезда глубины 1 — у детей тула `task` нет структурно). Wiring — в докстринге `core/subagents/__init__.py`. Ключевое: `SubagentResult.try_set_terminal` — first-writer-wins (владение: executor → COMPLETED/FAILED, task-тул → TIMED_OUT/CANCELLED; отмена в executor НЕ терминализирует, а перебрасывает); причина капа — аддитивное поле `stop_reason`, не новый статус; квитанции (`receipts.py` — формат+парсер+верификатор+промпт в одном модуле), верификация цитат по снапшоту леджера цитирующего хода; лимиты — `SubagentLimitMiddleware` (вырезание task-вызовов + `finish_reason=stop`; `max_concurrent`=`maxSubagents`, `max_total_per_run`=`maxTotalSubagents` из `limits` Сборки), admission — `SubagentCapacity` (FIFO, лимиты заморожены конструктором); события `task_*` — в custom-стрим. Два таймаута — из `limits` Сборки: `subagentTimeout` (потолок исполнения Сабагента, дефолт 600s из `SubagentConfig`) и `queueTimeout` (ожидание слота, дефолт 300s); резолвятся в `core/lead/graph.py::_lead_features`. Ребёнку НИКОГДА не передавать `configurable`-ключи в конфиг. Тесты герметичны: `tests/conftest.py` глушит tracing-флаги (LangSmith-автотрейсинг сериализацией фейк-модели выпивает её итератор — реальный пойманный баг).

Термины проекта — в `CONTEXT.md` (глоссарий); используй их в коде и обсуждениях.

## Security-ревью

Лид — авторизованный security-ревьюер кода (`core/lead/graph.py`, промпт `LEAD_SYSTEM_PROMPT`, референс strix). Инструменты: `report_finding` (фиксация Находки — severity/CWE/CVE/файл-строки/evidence/remediation; `core/tools/security/`), `load_skill` (справочник методик, `core/skills/` — курированные markdown-скиллы из strix по классам уязвимостей), `write_report` (резюме хода). Находки собираются из `report_finding`-tool_calls в истории сообщений (`collect_findings`, `collect_findings_from_events`) — без кастомного state. CVE-интеллект: cve-mcp-server (`infra/mcp.py`, `CVE_MCP_PATH` в .env → stdio через `uv run --project`) подключается как MCP, тулы уезжают за deferred-каталог (`core/tools/mcp/`); сервер недоступен ⇒ warn+continue. Скоуп — статический анализ кода; live-тулинг strix (browser/proxy/exploit) не портирован.

## Evals (evals/)

Офлайн-часть eval-харнеса по образцу ai-tutor-app: батарея = замороженный JSONL с запиненными `(repo_url, commit_sha)` и руками написанными бинарно-проверяемыми фактами (`evals/data/repos.v1.jsonl`; ground truth НИКОГДА не от LLM; правка = новый `_v2`-файл + запись в `DEPRECATED_BATTERIES`). `grade.py`/`validity.py`/`report.py` — офлайн и app-free (R1: не импортируют core/infra — грейд повторяем вечно): tri-state грейд (None = неизмеримо ≠ fail), tool-fair (structured + prose оценка каждого факта), validity-гейт исключает прогон из скоринга целиком, `price_run` — верхняя граница, неизвестная модель → None, не 0. Фаза платного прогона (`run_battery.py`) удалена вместе с durable-gateway — вернётся поверх раннера; константы приложения зеркалируются в `evals/common.py`. Прогоны с реальными деньгами — только по явной команде пользователя.

## Архитектура

Пишем по гексагональной архитектуре (ports & adapters): `core/` — домен и прикладная логика, не зависит от способа запуска: конфиг, пресеты памяти `core/memory/`; агент — `core/agents/` (фабрика `build_agent` + `RuntimeFeatures`, llm); лид — `core/lead/`; раннер — `core/runner/`; middleware фич — `core/middleware/`; сабагенты — `core/subagents/`; тулы — `core/tools/`, по папкам: `sandbox/` (`sandbox_run`/`read_file` над портом `core/ports.py::Sandbox` — `repo_dir`, `id`, `run`, `close`; `close()` отпускает локальные ресурсы, НЕ kill), `security/` (модель Находки + `report_finding`/`load_skill`/`write_report`, hub-персист в `hub.py`), `delegation/` (тул `task`), `mcp/` (тегирование + deferred-каталог `tool_search` с fail-closed сборкой); пакет `core/tools` пуст намеренно — импортируй из подпакетов (иначе цикл delegation → subagents → security). Адаптеры к внешнему миру — по краям (`infra/`, `migrations/`, `deploy/`, `runner.py`). Зависимости направлены внутрь: core не импортирует из runner.py и адаптеров.

## Commands

Основной путь — Taskfile (`task --list`): `task up`/`down` (инфраструктура: Postgres, RabbitMQ, OpenSandbox), `task migrate`, `task lint`/`fix`/`fmt` (ruff, конфиг в pyproject.toml), `task test` / `test:unit` / `test:integration` / `test:e2e`, `task check` (lint+test), `task runner` (раннер :8082), `task demo:runner`, `task backend:build|run|test|lint` (hub :8081; lint — golangci-lint, `backend/.golangci.yml`, ставится `go install .../golangci-lint/v2/cmd/golangci-lint@latest` под текущий toolchain), `task front` (vite :5173), `task app` (всё: hub + раннер + фронт). Напрямую: `uv add <package>` — зависимости (pyproject.toml руками не редактировать), `uv sync` — окружение.
