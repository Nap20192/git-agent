# runner — Delta Spec

## MODIFIED Requirements

### Requirement: HTTP API раннера

Раннер SHALL предоставлять HTTP API: `POST /instances/{id}/raise` (поднять Экземпляр), `POST /instances/{id}/events` (принять форвардженное Событие), `POST /instances/{id}/chat` (SSE-стрим хода чата в тред Экземпляра), `POST /instances/{id}/stop` (выгрузить), `GET /health` (живость + занятость слотов). Чат SHALL идти в тот же чекпоинт-тред Экземпляра и продлевать его активность.

Стрим чата SHALL отдавать кадры `token` (фрагмент ответа Лида по мере генерации), `message` (целое AI-сообщение — канон, заменяющий накопленные токены; единственный текстовый кадр, если провайдер не стримит), `activity` (статусная строка) и терминальный `done`; токены Сабагентов в стрим чата MUST NOT попадать. Реплики чата SHALL персистироваться в журнале хода (`hub.activity`) кадрами `chat_user {text}` и `chat_agent {text}`, чтобы hub отдавал транскрипт (`GET /api/instances/{id}/messages`) без раннера и после его перезапуска.

#### Scenario: Чат с Экземпляром
- **WHEN** приходит `POST /instances/{id}/chat` с сообщением
- **THEN** ход агента стримится SSE (`token`/`message`/`activity`/`done`) и записывается в тред Экземпляра

#### Scenario: Транскрипт чата переживает перезагрузку
- **WHEN** ход чата завершился и клиент заново открывает чат Экземпляра
- **THEN** реплика пользователя и ответ агента доступны из журнала хода как `chat_user`/`chat_agent`

#### Scenario: Health
- **WHEN** приходит `GET /health`
- **THEN** ответ содержит имя раннера, всего/занято слотов
