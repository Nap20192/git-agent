## Context

Агентный Ран — ReAct-лид (`build_lead_profile`), исполняемый воркером с
`AsyncPostgresSaver` под `thread_id=str(run_id)`; вся история сообщений (карта,
делегации, Находки, финальный ответ) — в чекпоинте. `Runtime` держит
`checkpointer`, `profile`, `make_model`, `provision_sandbox`, `store`. Песочницы
теперь без TTL + reconnect по id (`provision_sandbox(..., is_resume=True)`).

## Goals / Non-Goals

**Goals:**
- Продолжить диалог с лид-агентом поверх чекпоинт-треда завершённого Рана.
- Не трогать durable-модель Рана (submit/claim/lease/терминальный статус/Отчёт).
- Переиспользовать песочницу и инструменты агента.
- Стрим ответа + персист ходов для перезагрузки транскрипта.

**Non-Goals:**
- Чат для pipeline-режима (нет диалога).
- Слияние новых чат-Находок в Отчёт Рана (Отчёт остаётся снимком Рана; v2 при нужде).
- Мульти-юзер конкурентный чат одного Рана (сериализуем per-run).

## Decisions

**`Runtime.chat(run_id, message)` — не `submit`.** Чат — это `graph.astream(
{messages:[HumanMessage]}, config={configurable:{thread_id:str(run_id)}, **run_config})`
на пересобранном лид-графе (`profile.build` с тем же checkpointer). НЕ идёт через
admission/lease: Ран терминален, владельца нет, статус не пишем. Метод у `Runtime`,
т.к. там все зависимости; core не тянет infra (provision инъектирован).

**Модель и песочница — из строки Рана.** `store.get(run_id)` даёт llm_*-креды и
`sandbox_name`; `provision_sandbox(run_id, name, is_resume=True)` переподключается к
живому Экземпляру (иначе свежий+prepare). Песочница в конце хода `close()` (release,
не kill) — живёт для следующего сообщения.

**Персист отдельным типом `chat`.** Пользовательский и агентский ход пишутся
`store.add_event(run_id, "chat", {role, text})`. Историю/граф/Отчёт Рана это не
трогает: `graphview`/`report` читают `updates`/`custom`, а `chat` игнорируют.
Живой стрим (updates/custom чата) идёт клиенту, но НЕ персистится — на перезагрузке
виден транскрипт (роль+текст), без промежуточных tool-call'ов прошлых ходов.

**Сериализация — та же `event_to_wire`.** Чат-стрим кадрируется как события Рана
(reuse), с локальным инкрементным курсором (не durable seq). Транспорт — POST со
`StreamingResponse` (text/event-stream); фронт читает `fetch().body` reader (EventSource
не умеет POST).

**Сериализация ходов per-run.** `asyncio.Lock` на run_id в `Runtime` — два
параллельных сообщения одному Рану не переплетаются на треде/песочнице.

## Risks / Trade-offs

- **Дрейф Отчёта.** Новые Находки из чата не попадают в Отчёт Рана (снимок). Осознанно
  (non-goal); при нужде — отдельный «пересобрать Отчёт из треда».
- **Стоимость.** Живой агент с делегированием в чате может спавнить сабагентов — дорого.
  Лимиты Рана (`limits`) переиспользуются; можно ужесточить в v2.
- **Утечка песочниц.** Чат оживляет/держит Экземпляр; убийство — вручную через
  существующий kill (sandbox-lifecycle).
- **POST-SSE.** EventSource не POST-ит; фронт использует fetch-reader. Приемлемо.
