# security-analysis Delta

## MODIFIED Requirements

### Requirement: Структурированные Находки

В агентном режиме security-ревью система SHALL позволять агенту фиксировать Находки инструментом; Находка MUST нести severity (critical/high/medium/low/info) и краткое название, MAY нести класс уязвимости (CWE), CVE, расположение (файл/строки), impact, evidence, уверенность и шаги устранения. Отчёт агентного Рана MUST включать перечень Находок, зафиксированных КАК Лидом, ТАК И Сабагентами, с атрибуцией нашедшего; дубликаты объединяются, порядок — по severity. Отчёт MUST также нести сводку: распределение Находок по severity и итоговые счётчики.

#### Scenario: Агент фиксирует уязвимость

- **WHEN** агент в ходе ревью находит SQL-инъекцию и вызывает инструмент фиксации с severity=high и расположением
- **THEN** Находка попадает в Отчёт Рана с указанными полями

#### Scenario: Сабагент фиксирует уязвимость

- **WHEN** Лид делегирует проверку модуля, и Сабагент фиксирует SQL-инъекцию инструментом
- **THEN** эта Находка попадает в Отчёт Рана с атрибуцией к Сабагенту

#### Scenario: Сводка по severity

- **WHEN** Ран завершился с несколькими Находками разной критичности
- **THEN** Отчёт содержит распределение по severity и общее число Находок

#### Scenario: Ран без Находок

- **WHEN** агент завершает ревью, не зафиксировав ни одной Находки
- **THEN** Отчёт содержит пустой перечень Находок и резюме, а не ошибку
