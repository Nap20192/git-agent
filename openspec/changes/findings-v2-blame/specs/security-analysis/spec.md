# security-analysis — Delta Spec

## MODIFIED Requirements

### Requirement: Структурированные Находки

В агентном режиме security-ревью система SHALL позволять агенту фиксировать Находки инструментом; Находка MUST нести severity (critical/high/medium/low/info), краткий заголовок и файл, SHOULD нести описание, impact, уверенность (high/medium/low), категорию (injection/auth/crypto/secrets/deps/config/xss/ssrf/path/logic/other), MAY нести класс уязвимости (CWE), CVE, строки (lineStart/lineEnd), evidence, шаги устранения и ссылки (references). Для Находки с файлом и строкой раннер SHALL сам определить по `git blame` в Песочнице автора, email, коммит, дату (ISO) и первую строку сообщения коммита, а также introducedBy — `this_event`, если коммит входит в диапазон изменений текущего События (before..after либо merge-base..head), иначе `earlier`; без диапазона (полный аудит, чат) introducedBy не определяется. Модель blame не сообщает; значения инструмента имеют приоритет. Отчёт агентного Рана MUST включать перечень Находок, зафиксированных КАК Лидом, ТАК И Сабагентами, с атрибуцией нашедшего; дубликаты объединяются, порядок — по severity. Отчёт MUST также нести сводку: распределение Находок по severity и итоговые счётчики.

#### Scenario: Агент фиксирует уязвимость

- **WHEN** агент в ходе ревью находит SQL-инъекцию и вызывает инструмент фиксации с severity=high, файлом и строками
- **THEN** Находка попадает в Отчёт Рана с указанными полями и blame-атрибуцией строк

#### Scenario: Сабагент фиксирует уязвимость

- **WHEN** Лид делегирует проверку модуля, и Сабагент фиксирует SQL-инъекцию инструментом
- **THEN** эта Находка попадает в Отчёт Рана с атрибуцией к Сабагенту

#### Scenario: Сводка по severity

- **WHEN** Ран завершился с несколькими Находками разной критичности
- **THEN** Отчёт содержит распределение по severity и общее число Находок

#### Scenario: Ран без Находок

- **WHEN** агент завершает ревью, не зафиксировав ни одной Находки
- **THEN** Отчёт содержит пустой перечень Находок и резюме, а не ошибку

#### Scenario: Строки внесены текущим Событием

- **WHEN** Находка указывает на строки, чей blame-коммит достижим из after, но не из before диапазона События
- **THEN** introducedBy = this_event, автор и дата коммита записаны в Находку

#### Scenario: Находка без файла

- **WHEN** агент вызывает инструмент фиксации без файла
- **THEN** инструмент возвращает текст ошибки с требованием указать файл, Находка не записывается

## ADDED Requirements

### Requirement: Структурированный Отчёт хода

Инструмент записи Отчёта SHALL принимать структуру: summary, scope (тип События, диапазон before/after либо base/head, затронутые файлы, число изменённых строк), method (применённые инструменты/анализаторы), topRisks, recommendations, limitations. Система SHALL дополнить её счётчиками Находок по severity и Находками хода (с blame) и сохранить структуру рядом с текстовым summary; summary SHALL быть markdown-рендером той же структуры с таблицей Находок (severity, title, file:lines, blame author @ date, cwe, confidence), чтобы потребители старого поля видели полный отчёт. Не заданные моделью тип События и диапазон система SHALL подставить из События.

#### Scenario: Отчёт PR-ревью

- **WHEN** Лид завершает ход по pull_request и вызывает запись Отчёта с summary, method и рисками
- **THEN** сохранённая структура содержит eventType=pull_request, диапазон merge-base..head, счётчики и Находки, а summary — markdown с таблицей Находок
