# Пользователи и OAuth-связки

Type: wayfinder:grilling
Status: closed
Assignee: vnkjd
Blocked by: —

## Question

Локальные пользователи или OAuth-вход, механизм аутентификации API, тип OAuth-приложения, хранение токенов, число связок, привязка Репозиториев к связке.

## Answer

Референс UX — Railway: «подключи репозиторий — на события что-то срабатывает».

- **Вход — кнопкой «Sign in with GitHub/GitLab»**, паролей нет вовсе. Первый вход создаёт пользователя и его первую связку одним OAuth-флоу. (Отменяет решение чартинга «пользователи локальные, OAuth не для логина».)
- **Сессии**: opaque session-токен в БД, cookie.
- **OAuth App** у обоих провайдеров (симметрично); GitHub App (repo-scoped установка, как у Railway) — осознанный апгрейд потом.
- **Секреты шифруем**: OAuth-токены и webhook-секреты — AES-GCM, ключ из env (`SECRETS_KEY`). Refresh-токены храним там же, refresh-флоу — по 401 от провайдера.
- **Связок много**: unique (provider, provider_user_id), у пользователя может быть несколько аккаунтов одного провайдера. Подключённый Репозиторий принадлежит пользователю и ссылается на связку, через которую его видим и вешаем хук (смерть связки ⇒ видно осиротевшие репо).
