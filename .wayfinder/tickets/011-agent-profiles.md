## Question

Критерий подписки Сборки, модель привязки N:M, веер на вебхуке, специализация раннеров.

## Answer

- **Подписка = тип действия + маска ветки** (v1): «пуши в release/*», «все PR». Фильтр по путям в diff («тронули src/auth/») — осознанно в план на потом (туман).
- **Таблица подписок** `hub.build_subscriptions` (build_id, repository_id, actions[], ref_mask) заменяет колонку `repositories.build_id` (миграция 002). **Фолбэк**: репо без подписок обслуживает дефолтная Сборка на все события.
- **Веер на вебхуке**: одно Событие → upsert Экземпляра каждой совпавшей Сборки → N строк outbox (в сообщении уже есть instanceId). Несколько агентов на одно событие — задуманное поведение; раннер и контракт сообщения не меняются.
- **Раннеры универсальные**: любой раннер поднимает любую Сборку; «Сборка → пул раннеров» — туман на будущее (задел: topic exchange).
